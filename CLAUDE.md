# Сайт kupdasha.ru — памятка для работы

Портфолио Дарьи Купцовой (Купяша): серьезная светлая версия и дружеская темная, переключаются тумблером. Прототип живет здесь, на сайт попадает через Тильду.

## Файлы
- `content.js` — все тексты, проекты, клиенты. Пары `['серьезно', 'по-дружески']`. Типограф в app.js сам ставит «ёлочки», тире, неразрывные пробелы и убирает точку у одиночного предложения.
- `index.html`, `about.html`, `speaker.html` — каркасы страниц; `style.css` — оформление; `app.js` — движок; `fun.js` — дружеская версия (ножки у кнопок, многоножка, иней, НЛО); `shimmer.js`, `waves.js` — переливы.
- `adhd.js`, `adhd.css` — живые главы кейса СДВГ (грузятся сами из app.js).
- `fleet.js`, `fleet.css` — живые главы кейса Nέofleet (грузятся сами из app.js); картинки и SVG-слои разметки — в `img/neofleet`.
- `img/` — свои картинки и видео; на сайт идут с GitHub через jsDelivr (пути `img/…` app.js сам переводит на адрес GitHub).
- `tilda/build.py` → `tilda/блоки/*.txt` — готовые блоки «HTML-код» для Тильды; `tilda/проверка.html` — все блоки подряд, как их выведет Тильда.
- `taplink.html` — таплинк (один экран: четыре кнопки и соцсети, жидкость из искр, в веселой версии кнопки на ножках с другими надписями). Самодостаточный файл, его и правим. На Тильде — отдельная страница без общей шапки и подвала с одним блоком `tilda/блоки/5 таплинк`: он подтягивает taplink.html с GitHub целиком, поэтому любые правки уходят на сайт через `./tilda/publish.sh`, блок не перевставляется.
- Превью: конфиг studia-preview (порт 8641) → http://localhost:8641/kupdasha/

## Как устроены проекты
Поля проекта в `SITE.works.items`: `title`, `year` (маленькая цифра у названия; годы не дублировать в тегах и описаниях), `tag`, `short` (пара), `image`, `pos` (сдвиг обложки), `video`, `preview` (тихое видео для сетки: mp4, Vimeo или Kinescope), `ratio` (пропорции ролика, если не 16:9), `note` (приписка под описанием кейса), `heroNote` (подпись под роликом), `deck` (презентация после описания: `drive:ID` — окно с PDF, или список картинок — слайды один под другим), `brandkit` (живой блок «логотип и цвета», см. MAX), `thermal` (живое поле градиента-тепловизора с логотипом и палитрой, нагревается курсором, см. Школу авторов), `heroImage` (своя картинка в шапке кейса, если она отличается от обложки в сетке), `heroRatio` (шапка в пропорциях картинки — целиком, без увеличения; карточка в сетке не меняется, см. СДВГ), `deckTitle` (крупная надпись над презентацией), `audit` (аудит как дизайн-кейс: главы с живой инфографикой — audience, formula, traffic, journey, search, compare, plus, friction, lowercase, glass, rows, world; рисует audit.js, стили audit.css, оба грузятся сами из app.js; см. divan.ru; живые графики из сухих цифр — textChart (абзац → график), curve, columns, shift, rank, phoneTable (таблица → телефон), zoomPhone, palette, с `auditTheme: 'edb'` в цветах ЕАБР, см. сайт ЕАБР), `adhd` (кейс как рассеянное внимание: главы thoughts — фразы расплываются вокруг фокуса, board — наброски вразброс собираются в сетку при прокрутке, type — живая типографика на SVG, versions — футболки сами перескакивают между версиями, курсор листает, details — карточки качаются как брелоки, final, press — издания со ссылками; рисует adhd.js, стили adhd.css; см. СДВГ), `fleet` (кейс как дорога: road — слоганы едут по полосам, наведение переводит; refs — референсы встречными потоками при прокрутке; colors — цвета ткани, ряды макетов разъезжаются; search — варианты разметки, колесо катится по дороге; mark — живой финал: SVG-слой из Фигмы поверх чистого худи, разметка наносится, колесо подкатывается, наведение — пунктир бежит; lights — курсор-фары; prompt — шторка макет/кадр и запрос к нейросети; look — лента съемки едет с прокруткой; рисует fleet.js, стили fleet.css; см. Nέofleet), `world` (живое 3D-пространство из Marble: файлы .spz берутся из api.worldlabs.ai/api/v1/worlds/ID → spz_urls, кладутся в img; показывает world.js на Spark; встроить страницу Marble нельзя — она запрещает iframe; см. divan.ru), `gallery` (элемент-список `[...]` — несколько блоков подряд; живые блоки брендбука `{head}`, `{blend}` цвета сливаются в градиент, `{spin}` вращающиеся градиенты, `{float3d}` левитирующие 3D-иконки, `{icons2d}` анимированные 2D и правила; коллаж `cover: true` обрезает фото по ячейке — всё см. Школу авторов), `story` или `scheme` {task, role, solution, result}, `labels`, `links`, `frost`, `other: true` (в «другие работы»).
Порядок в списке = порядок на сайте. Первые пять — сильнейшие кейсы для лида.

## Тильда
- Страницы: «Шапка» (оформление + шапка и общие тексты), страницы сайта (разделы с разметкой и своими текстами), «Подвал» (служебные элементы и код).
- ВСЁ содержимое (content.js: тексты, проекты, обложки) тоже лежит на GitHub и подключается в блоке «шапка и общие тексты». Блоки Тильды — только разметка разделов и загрузчики; их перевставлять, лишь если менялась разметка (index.html и т. п.). Пользователь ничего не переносит руками.
- На Тильде нет `<main>` (обертка `#allrecords`), ссылки с `#` перехватывает ее прокрутка — кейсы открывать кодом.
- Код (content.js, style.css, app.js, waves.js, fun.js, shimmer.js) и папка img лежат на GitHub kupdasha/my-site (публичный) и подключаются в Тильде через jsDelivr. Блоки «оформление» и «код сайта» — только ссылки, их не перевставлять.
- После правки кода или картинок: `./tilda/publish.sh "что изменилось"` — пересоберет блоки, отправит на GitHub и сбросит кеш jsDelivr. Сайт обновится сам; браузеры подхватят в течение часа (параметр ?v= меняется раз в час).
- Правка видна на сайте только после `./tilda/publish.sh` — после каждой законченной правки публиковать. Перед публикацией: node --check для js, все файлы img на месте.

## Правила дизайна (обязательные)
Без оранжевого (даже в радугах), без символа «·», без нумерации «01/02», фейковых метрик, капса, эмодзи-иконок, текста мельче 16px, моноширинного ради стиля, карточек в карточках, стекла, неонового свечения. Короткие крупные заголовки и кнопки — строчными. Все кнопки с заливкой, контурные — только теги. В серьезной версии кнопки черные и без буквенных анимаций. Цифры и факты не выдумывать — спрашивать. Личную страницу ВКонтакте не указывать. Переносы: одно слово никогда не остается последней строкой (типограф держит его за предыдущим), предлоги и союзы уходят вниз вместе со словом; короткие приписки — text-wrap: balance.

## Работа по кейсам
Каждый крупный кейс — отдельный чат в группе «Сайт kupdasha.ru». В начале чата назвать кейс; после работы пересобрать блоки. Крупные кейсы планируем выносить на отдельные страницы Тильды (шаблон делаем на MAX).

## Структура версий
Веселая версия повторяет структуру серьезной один в один: те же разделы в том же порядке. Если в серьезной что-то добавили, убрали или переставили — так же и в веселой; отличаются только тексты и анимации. Струны со звуком живут в «других работах» (в серьезной там простые линии). В фильтрах проектов по умолчанию выбран «дизайн» (works.startFilter).
