# Сайт kupdasha.ru — памятка для работы

Портфолио Дарьи Купцовой (Купяша): серьезная светлая версия и дружеская темная, переключаются тумблером. Прототип живет здесь, на сайт попадает через Тильду.

## Файлы
- `content.js` — все тексты, проекты, клиенты. Пары `['серьезно', 'по-дружески']`. Ссылка внутри абзаца — `[слово](https://адрес)`. Типограф в app.js сам ставит «ёлочки», тире, неразрывные пробелы и убирает точку у одиночного предложения.
- `index.html`, `about.html`, `speaker.html` — каркасы страниц; `style.css` — оформление; `app.js` — движок; `fun.js` — дружеская версия (ножки у кнопок, многоножка, иней, НЛО); `shimmer.js`, `waves.js` — переливы.
- `adhd.js`, `adhd.css` — живые главы кейса СДВГ (грузятся сами из app.js).
- `fleet.js`, `fleet.css` — живые главы кейса Nέofleet (грузятся сами из app.js); картинки и SVG-слои разметки — в `img/neofleet`.
- `clip.js`, `clip.css` — живые главы музыкального клипа (грузятся сами из app.js); стоп-кадры из готового клипа, лицо для мозаики и спрайт миниатюр — в `img/clip`. Волны дорожек и цвета секунд посчитаны по файлам песни и клипа и лежат прямо в clip.js.
- `armani.js`, `armani.css` — живые главы кейса Armani Casa (грузятся сами из app.js); картинки и ролики — в `img/armani`.
- `kav.js`, `kav.css` — живые главы кейса «Одна кавычка» (грузятся сами из app.js); фото и короткие ролики — в `img/kavychka`.
- `vkplay.js`, `vkplay.css` — живые главы кейса «VK Play, универсальный стенд» (грузятся сами из app.js); рендеры — в `img/vkplay`, исходники рендеров для доработки нейросетью — `исходники/vkplay-renders.zip` (в git не идет).
- `suit.js`, `suit.css` — живые главы кейса «Парашютный костюм Skolkovo» (грузятся сами из app.js); картинки — на Тильде, новых нет.
- `ventures.js`, `ventures.css` — живые главы кейса The Ventures Japan (грузятся сами из app.js): в шапке кейса вместо картинки живой принт на canvas — плитки с сакурой по геометрии из Figma едут от подола вверх и тают, на сплошном синем с белым логотипом, верх шапки срезан; главы tile (кольцо из двух рядов «десять шагов», крутится от движения курсора, в центре две крупные плитки), look (съемка, крупно по нажатию), tokyo (фото с мероприятия). Векторы плитки, логотипа, award и слогана (шрифты в кривых) и фото — в `img/ventures`.
- `akbars.js`, `akbars.css` — живые главы кейса знаков отличия Ак Барс Банка (грузятся сами из app.js); рендеры и чертежные маски — в `img/akbars`.
- `vector.js`, `vector.css` — живые главы кейса «векторизатор» (грузятся сами из app.js): one — функции Иллюстратора гаснут, остается трассировка; zoom — лупа растр/вектор со шторкой; steps — пять шагов трассировки на коте 38×64; knobs — ползунок «точность кривых», число точек настоящее; gen — промт печатается, картинка появляется и обводится. Картинки и SVG в `img/vector` — настоящие ответы генератора (воркер vector-ai) и векторизатора; контуры для steps и knobs посчитаны функциями самого векторизатора и лежат прямо в vector.js.
- `navi.js`, `navi.css` — живые главы кейса «Студия дизайна навигации» (грузятся сами из app.js): в шапке 3D-ролик, написанный кодом (кампус Бауманки на холсте, сцены, титры из content.js), конструктор таблички со сверкой по ТЗ, 3D-кампус с режимами «студия / заказчик»; картинок нет, всё рисуется кодом.
- `anon.js`, `anon.css` — живые главы кейса «анонимайзер» (грузятся сами из app.js, поле `anon`): swap — крупное слово перебирается буква за буквой в выдуманное той же длины, риски под знаками, падежи одной заменой; doc — лист договора, вкладки «оригинал / обезличенный» с таймером, от логотипа и печати остаются пустые рамки; inside — окно браузера, маркер проходит по частям файла, запросов в интернет 0; back — ответ нейросети, кнопка возвращает настоящие имена; try — кнопка демо. Слова в `{скобках}` в content.js — то, что заменяется; словарь общий на кейс («Ромашка» → «Тавеслу»). Картинок нет.
- `img/` — свои картинки и видео; на сайт идут с GitHub через jsDelivr (пути `img/…` app.js сам переводит на адрес GitHub).
- `tilda/build.py` → `tilda/блоки/*.txt` — готовые блоки «HTML-код» для Тильды; `tilda/проверка.html` — все блоки подряд, как их выведет Тильда.
- `taplink.html` — таплинк (один экран: четыре кнопки и соцсети, жидкость из искр, в веселой версии кнопки на ножках с другими надписями). Самодостаточный файл, его и правим. На Тильде — отдельная страница без общей шапки и подвала с одним блоком `tilda/блоки/5 таплинк`: он подтягивает taplink.html с GitHub целиком (сначала raw.githubusercontent — свежая версия через пару минут, если не ответил за 4 с — jsDelivr), поэтому любые правки уходят на сайт через `./tilda/publish.sh`, блок не перевставляется.
- Превью: конфиг studia-preview (порт 8641) → http://localhost:8641/kupdasha/

## Тильда
- Страницы: «Шапка» (оформление + шапка и общие тексты), страницы сайта (разделы с разметкой и своими текстами), «Подвал» (служебные элементы и код).
- ВСЁ содержимое (content.js: тексты, проекты, обложки) тоже лежит на GitHub и подключается в блоке «шапка и общие тексты». Блоки Тильды — только разметка разделов и загрузчики; их перевставлять, лишь если менялась разметка (index.html и т. п.). Пользователь ничего не переносит руками.
- На Тильде нет `<main>` (обертка `#allrecords`), ссылки с `#` перехватывает ее прокрутка — кейсы открывать кодом.
- Код (content.js, style.css, app.js, waves.js, fun.js, shimmer.js) и папка img лежат на GitHub kupdasha/my-site (публичный) и подключаются в Тильде через jsDelivr. Блоки «оформление» и «код сайта» — только ссылки, их не перевставлять.
- Загрузчик (LOADER в tilda/build.py, стоит в блоке «оформление»): файлы берутся с jsDelivr не по ветке main (ее копию jsDelivr держит до 12 часов), а по номеру последнего коммита, который сайт спрашивает у GitHub API. Любой push на сайте виден за минуту; браузер, уже знающий номер, грузится по нему сразу и узнает новый в фоне — после публикации обновить страницу два раза. Если блоки на Тильде еще старые (с `@main/` и `?v=`), правки ждут jsDelivr до 12 часов — тогда перевставить «оформление», «шапку и общие тексты» и «код сайта».
- После правки кода или картинок: `./tilda/publish.sh "что изменилось"` — пересоберет блоки, отправит на GitHub, сбросит кеш main и прогреет новую версию на jsDelivr (`tilda/warm.sh`: по новому номеру jsDelivr первый раз собирает файлы ~10 с). Если коммитишь сам, не через publish.sh (например, только свои файлы, когда в папке чужие незаконченные правки), — после `git push` запусти `./tilda/warm.sh`.
- Правка видна на сайте только после `./tilda/publish.sh` — после каждой законченной правки публиковать. Перед публикацией: node --check для js, все файлы img на месте.

## Правила дизайна (обязательные)
Без оранжевого (даже в радугах), без символа «·», без нумерации «01/02», фейковых метрик, капса, эмодзи-иконок, текста мельче 16px, моноширинного ради стиля, карточек в карточках, стекла, неонового свечения. Короткие крупные заголовки и кнопки — строчными. Все кнопки с заливкой, контурные — только теги. В серьезной версии кнопки черные и без буквенных анимаций. Цифры и факты не выдумывать — спрашивать. Личную страницу ВКонтакте не указывать. Переносы: одно слово никогда не остается последней строкой (типограф держит его за предыдущим), предлоги и союзы уходят вниз вместе со словом; короткие приписки — text-wrap: balance.

## Работа по кейсам
Каждый крупный кейс — отдельный чат в группе «Сайт kupdasha.ru». В начале чата назвать кейс; после работы пересобрать блоки. Крупные кейсы планируем выносить на отдельные страницы Тильды (шаблон делаем на MAX).

## Структура версий
Веселая версия повторяет структуру серьезной один в один: те же разделы в том же порядке. Если в серьезной что-то добавили, убрали или переставили — так же и в веселой; отличаются только тексты и анимации. Струны со звуком живут в «других работах» (в серьезной там простые линии). В фильтрах проектов по умолчанию выбран «дизайн» (works.startFilter).
